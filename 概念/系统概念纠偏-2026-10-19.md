# 系统概念纠偏：预测、推理与执行

日期：2026-10-19。依据用户主动复述整理；本次已说明，尚未确认掌握。此笔记为课程反馈补充，不是新一期日报。

## 活动手册题

已表现：能主动查时效性、限定身份、识别查不到新版时需披露。进一步区分：旧文件不必然无效，最新发布也未必已经生效；应核对当前适用版本、活动届次、勘误和权威出处。可靠系统时间可作为当前日期依据，不必每次都联网校时。

## 各组件的工作定义

| 概念 | 更准确的理解 | 需要避免的等同 |
| --- | --- | --- |
| LLM | 常见自回归模型将上下文变成数值表示，经神经网络计算后生成下一token的分布；可以学到并执行推理模式，但会出错 | 反向扩散追溯元语义；预测就没有推理；高概率就是高真实性 |
| Prompt | 提供目标、材料、例子、约束与输出要求，改变这次生成的条件 | 临时修改模型权重或给出精确的向量方向 |
| Skills | 可按需加载的任务指令与资源包，可含脚本、示例和参考文件 | 只要保存Markdown就成为会自动执行的技能；新的向量标准 |
| RAG | 检索外部资料并辅助生成 | 所有记忆或永久学会知识 |
| MCP | 让应用与外部服务交换工具及上下文的连接协议 | 工具本体、浏览器本体、全部Agent都必须使用的机制 |
| Agent | 围绕目标依据反馈选择动作并推进任务的系统 | 只负责管理文字输出 |
| Harness | 运行Agent的支撑：组织上下文、调用工具、管理状态、边界和结束条件 | 必定在Agent之外的上级治理层；只改善输出 |
| Loop | 行动→观察反馈→决定继续、重试或结束 | 必须源自CoT；每轮自评就保证越来越正确 |
| CoT | 将问题分解为中间推理步骤的一类方法 | 外部验证机制；可见解释必然完整还原内部过程 |

## 同一个例子

要知道今年活动到场时间：模型分析问题；Prompt明确身份与年份；Skills可规定查证步骤；RAG找出手册片段；工具实际访问网页，可能经MCP连接；Agent决定下一步查什么；Harness传递结果、管理状态与限制；Loop在发现版本不符后补查。CoT可以帮助分解问题，但能否核实结论仍取决于证据与检查方法。

这是帮助区分职责的教学地图，不是所有产品都按此拆成独立模块。

## 后续理解反馈

用户已能区分模型形成结果与计算器外部核验。补充：调用工具与发现错误属于循环中的行动、观察环节，还要依据反馈决定修正、重试或停止。示例：模型算出17 → 计算器返回19 → 比较发现不一致 → 检查步骤并修正或继续验证 → 满足条件后结束。不能将单次工具调用本身等同于完整Loop。
