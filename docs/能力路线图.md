# 能力建立路线图

更新：2026-10-22。目标：从理解机制，逐步做到能借助AI完成开发、解释关键代码、运行和修改一个有来源、可检查、可部署的应用。起点是AI初学者、编程基础待确认；不把读过或复制运行成功记为独立掌握。

## 贯穿项目：自己的AI学习助手

先用现有日报与概念笔记做材料，逐步实现：读取Markdown → 按条件查找 → 带来源回答 → 调用工具 → 记住明确反馈 → 提供接口 → 部署。首个业务场景暂用这个熟悉的知识库，之后可按兴趣替换。

目前日报生成和网页发布由Codex协助完成。这是可用的项目起点，不代表用户已独立掌握构建它所需的能力。无需为课程立即购买API或硬件；涉及模型调用时，先解释选项，使用无需密钥的样例或模拟数据练习程序结构，真实调用另作明确配置。

## 阶段1：模型与信息基础

内容：Token、Embedding（语义向量）、Context、模型幻觉；Prompt的目标、材料、角色、输出格式、边界与回答稳定性。区分参数、输入与外部记录。

练习：用同一段通知改变一个条件，比较回答；用示意图理解语义相近与事实正确的区别；为固定任务写明确的输出要求与检查项。

验收：能解释“语义接近不代表事实成立”“结构符合要求不代表内容准确”；能识别当前材料缺什么。已有时效、对象、信息路径方面的应用反馈保留；其他概念按需补，不从头机械重讲。

## 阶段2：Python、异步与FastAPI

顺序：环境与运行方式 → 变量/列表/字典 → 条件与循环 → 函数 → 文件与JSON → 异常 → HTTP请求与响应 → async/await、并发、超时与重试 → FastAPI接口、输入校验与错误返回。

练习：读一篇日报并输出日期/标题；处理文件不存在；比较串行和并发等待；把日报查询包装成一个可访问接口。每个例子先读懂输入输出，再运行，最后自己改一个条件。

验收：能运行并解释小程序，独立改一个字段或条件；能区分等待I/O与计算；接口收到错误输入能明确报错。异步与FastAPI不作为第一课就直接跳入的内容。

## 阶段3：RAG、工具、记忆与规则

RAG：文档解析 → 切分 → 保留元数据 → Embedding → 索引与检索 → 必要的筛选/重排 → 带证据生成 → 检索与回答分别检查。先理解最小链路，再逐步增加组件。

工具：定义工具参数和返回结果；理解模型提出调用请求、程序执行、结果返回，再到下一步决定；处理超时、错误及重复执行。MCP按连接需要加入，不当作工具本身。

记忆：区分当前上下文、会话状态、长期记录；学习写入、召回、更新、冲突与遗忘。规划、拆解、执行是任务控制行为，可以利用记忆，不直接等同于短期/长期记忆。

规则与Harness：输入约束、状态、权限、工具执行、输出校验、反馈循环和停止条件。规则不是只靠一段Prompt便能保证执行。

验收：能搭出带来源的最小知识问答；资料不足时拒绝编造；能观察一次工具失败后的处理；新反馈可被保存、找回并正确限定范围。

## 阶段4：框架与数据工程

先在最小实现上选择LangChain或LlamaIndex其中一个实践，再对照另一个的适用边界，不同时背两套API。框架的版本、用法与限制在上课当天查官方文档。

数据：理解原文、元数据、任务状态和向量索引各自职责；体验一种向量存储，学习增删改查、版本、持久化、备份恢复与部署。先解决数据如何可靠保存，再比较工具。

验收：能说明框架替自己做了什么；文档修改后索引能更新，删除后不再被引用，重启后数据还在。先做小规模样例，不为了学习先搭复杂集群。

## 阶段5：本地模型、量化与部署

内容：模型文件、推理服务、内存/显存、上下文与并发；量化在体积、资源占用、速度与任务质量之间的取舍。基于实际设备再选模型，不预设一定更快或更好。

练习：记录设备条件；比较同一组小任务在不同配置下的结果和耗时；将已完成的服务部署并观察日志、超时、失败恢复。API费用、密钥管理及公开访问范围在真实使用前说明。

验收：能解释配置选择的证据与局限，服务可访问、可停止、可恢复；不会把“能启动”当成“业务可用”。

## 阶段6：完整业务落地

把知识库助手做成完整闭环：明确用户与问题 → 定义验收 → 准备资料 → 实现 → 评测 → 部署 → 观察真实使用 → 修正。评测从阶段1持续穿插，不等项目最后才补。

验收：新用户能完成核心任务；答案可回查，缺资料可解释；有固定检查题、更新记录、备份及成本/耗时观察。能自行修改一个需求，并验证其他功能没有退步。多Agent协作按任务确有需要时再加入。

## 每日安排与进度规则

继续每天约15分钟，一半最新进展、一半系统学习。系统学习每天只推进一个小目标，依次采用“图解/生活例子 → 阅读极短示例 → 运行 → 改一个条件”；概念课不强行加代码。

基础未确认时先给可理解的示例，不默认用户会终端、Python或HTTP。实践可跨日拆成小步；需要额外时间的练习明确标作可选，不把它隐藏在15分钟预算里。若实际目标需要更多练习，如实说明，不承诺仅靠每日阅读就能形成工程能力。

每课标出所属阶段、前置知识、当天目标和一个可观察的检查点。每周自然穿插一次复习或小整合，仍保留新闻部分；不按日历自动晋级。状态区分：待学、已介绍、在本例能应用、能独立完成；升级须有真实回答或操作证据。

2026-10-23：Embedding与相似性/事实性边界已介绍，等待反馈，不标记掌握。下一课建议：Python最小基础，用日报标题和日期理解数据与输入输出，再分步运行和修改；按反馈交替推进概念与操作，已有信息路径与证据检查能力继续复用。用户可随时调整节奏与项目。
